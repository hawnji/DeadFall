# Project Deadfall

A class-based military zombie survival FPS for PC. Two to four players deploy from a walkable forward operating base into procedurally assembled infected sites, survive escalating waves of the Blight, complete objectives, build temporary run builds, and earn permanent progression.

> Working title. See `DECISIONS.md` (D-20).

## Setting up the project

The Unity editor files (`ProjectSettings/`, `Packages/`) are generated by Unity, not hand-written, so the first setup is:

1. Install **Unity Hub** and **Unity 6 LTS** (6000.0.x) with *Windows Build Support (Mono/IL2CPP)*.
2. In Unity Hub: **New project → Universal 3D** template. Name it `ProjectDeadfall` and create it **in an empty folder**.
3. Close Unity. Copy the generated project's `Assets/` (keep everything), `Packages/`, and `ProjectSettings/` into your clone of this repository, so `Assets/_Project` from the repo sits alongside the template files. Run `git lfs install` once, then open the clone in Unity Hub (**Add → Add project from disk**).
4. Open the project. In **Window → Package Manager**, install:
   - Input System (accept the restart and enable the new backend)
   - Netcode for GameObjects
   - Multiplayer Services
   - AI Navigation
   - Multiplayer Play Mode
   - Newtonsoft Json (`com.unity.nuget.newtonsoft-json`, add by name)
   - Test Framework (normally pre-installed)
5. **Project Settings → Player → Other Settings**: Api Compatibility Level `.NET Standard 2.1`, Scripting Backend `IL2CPP` for release builds (Mono is fine for day-to-day work).
6. **Project Settings → Editor**: Enter Play Mode Options enabled, with domain and scene reload disabled. Our code must tolerate this (see `ARCHITECTURE.md` §9).
7. Commit `Assets/`, `Packages/manifest.json`, `Packages/packages-lock.json`, and `ProjectSettings/`.

## Running

Nothing is playable yet. From M1 on:

- Open `Assets/_Project/Scenes/Sandbox/Sandbox_Movement.unity` and press Play.
- Tests: **Window → General → Test Runner**, run EditMode then PlayMode.
